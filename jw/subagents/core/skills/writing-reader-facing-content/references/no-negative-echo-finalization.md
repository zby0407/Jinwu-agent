# Accepted-state finalization checklist

Use this checklist after a user correction, a discarded framing, or a long
revision session.

1. Write down the accepted target state internally.
2. List facts the audience needs and session-only alternatives that should stay
   in work/status context.
3. Regenerate high-salience surfaces from the accepted body: title, subtitle,
   opening, headings, filename, labels, captions, metadata, and handoff.
4. Retain an exclusion only when omission would make the artifact unsafe,
   inaccurate, misleading, incompatible, incomplete, or noncompliant, or when
   the user requests a comparison, audit, quotation, changelog, migration note,
   or decision record.
5. Re-read the complete final bundle after every change. An exact-term scanner
   is a supplementary check for text and filenames; it cannot detect semantic
   paraphrases or prove that the writing is complete.

## Source and adaptation note

This local checklist adapts the accepted-state and surface-by-surface review
pattern from [LB623/no-negative-echo](https://github.com/LB623/no-negative-echo),
licensed under MIT. The external project describes the pattern as prompt-level
mitigation and keeps deterministic scanning separate from semantic review. This
skill keeps that boundary and combines it with the local evidence, audience, and
format-quality gates.
