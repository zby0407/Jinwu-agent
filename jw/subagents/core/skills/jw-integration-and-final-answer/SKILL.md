# JW 科研整合与最终回答

## 核心原则

最终回答是声明级（claim-level）证据整合，不是对子 Agent 文本投票或拼接。`blocked`、负结果、低功效和证据不足可以构成完整回答，但不能被润色成已支持结论。

## 整合矩阵

每个关键声明建立一行：

| 字段 | 要求 |
|---|---|
| 声明 | 可单独判断真伪，区分描述、预测与机制 |
| 数据 | 实际使用的数据、时间窗和可绑定回执 |
| 方法/结果 | 真实执行结果、基线和不确定性 |
| 文献 | 仅说明外部相容性，不替代本任务实证 |
| 冲突 | 哪个角色或工件给出不同结论及原因 |
| verdict | `supported`、`mixed`、`unsupported`、`insufficient_evidence` 或 `blocked` |
| 下一步 | 最小可判别实验或解除阻塞条件 |

确定性数据回执和真实执行结果限定事实边界；Evidence 的声明级审查限定结论强度。模型自述、页面完整度和多数角色同意都不能覆盖缺失数据或失败实验。

## 冲突处理

1. 数据未实际进入实验时，相关声明保持 `blocked`，即使机制文献相容。
2. 历史描述支持不自动升级为样本外预测；预测相关不自动升级为因果机制。
3. 正负交互都无支持时，保留零模型、regime 或低功效解释，不强迫方向。
4. 不足三个获支持假设时，如实输出不足三项的支持集合；研究优先级可以继续列三项，但必须另表。

## 最终回答结构

先直接回答原始问题，再给：关键结论、支持度与研究优先级、最重要证据、不确定性、下一实验。读者可见中文不打印内部 stage、A2A handoff、路径或调试过程；必要的 English 专业名词与状态值原样保留。

## 回答与发布分层

- **回答完成**：即使 verdict 为 `blocked` 或 `insufficient_evidence`，只要原因和下一步清楚，也可完成。
- **允许发布**：只有声明、数据、方法、结果和引用经过发布质检且结论强度一致时才进入正式 release。

## 常见错误

| 错误 | 修正 |
|---|---|
| 把六份摘要直接合并 | 先做声明级矩阵 |
| 为凑三个结论而升级证据 | 分开支持集合与研究组合 |
| 把文献机制当本次实证 | 标记 mechanism-compatible |
| 把完整回答等同正式发布 | 分开 answer 与 release gate |
