# Native and GUI Bridge Routing for Contest Figures

Use this reference when a native or GUI bridge may materially improve a
mathematical-modeling figure's layout, editable source, render quality, export,
or verification.

## Principle

Scripts provide repeatable data and computation. A native bridge can be the
primary authoring surface when it creates a stronger judged artifact. Select
the route by figure type, mathematical source, topology, readability,
reproducibility, and demonstrated availability.

## Capability Proof

Before claiming a native route succeeded:

1. obtain authorization for interactive or cloud-visible control when needed;
2. open or inspect the target or a minimal route-test artifact;
3. perform a real edit, render, execution, save, or export;
4. inspect the output and, if embedded, inspect it at paper insertion width;
5. record the receipt or failure reason in the project validation record.

Do not describe a substitute figure as if a native route had been demonstrated.

## QA Evidence

For each final formal figure, retain the editable source when available, export
path, standalone-preview status, inserted-page-preview status, and fallback
reason. Keep this evidence internal unless the user or contest asks for a full
internal archive. Host-specific application details and staging procedures
belong in `runtime-adapters/windows-native-bridge.md`.
