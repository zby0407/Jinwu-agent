# JW 科学声明一致性

## 核心原则

同一声明只从一个当前权威工件派生。文稿之间互相抄写不是证据链；遇到冲突时回到回执、CSV 和正式状态，而不是按多数文本或较新措辞裁决。

## 声明账本

在撰写或更新多份成品前，为每个关键声明记录：

| 字段 | 内容 |
|---|---|
| `claim_id` | 稳定标识，例如 `h2.primary.skill` |
| 含义 | 描述性关系、预测技能、机制或发布决定 |
| 权威来源 | 回执及精确 JSON 字段，或 CSV 行列 |
| 数值与单位 | 点估计、基线、差值、区间、样本数 |
| 时间边界 | as-of 日期、forecast origin、最终或暂定标签 |
| verdict | 当前接受状态及允许的读者表述 |
| 使用位置 | 报告、综合文稿、展示稿和图注 |

数值首次进入账本时从机器工件读取。后续文稿由账本生成或核对，不重新心算、不从旧文稿复制。

## 三份文稿的专项核对

对“三个优先假设”“历史回测与 SC26 预测”“P5–P6 评委展示稿”至少核对：

1. H2 的 `candidate_mae`、基线 MAE、`mae_improvement`、bootstrap 区间和逐折改善来自同一升级回执。`improvement_by_fold` 不能与 leave-one-fold 敏感性结果混用。
2. SC25 暂定前瞻检查与 SC20–24 历史技能门分开；不得把暂定点加入技能 verdict。
3. SC26 点预测、区间、数据截止和模型名称在综合报告与展示稿一致；早期先验只作为历史版本。
4. H3 在没有登记的轴向偶极矩或可复算日面拼图时保持 `blocked_by_data`。
5. 图中文字、图注、正文和表格都属于声明表面，必须一起检查。

## 冲突处理

- 权威回执与文稿冲突：修正文稿，并记录受影响的全部成品。
- 两个回执冲突：先区分任务、数据截止、forecast origin 和 accepted 状态；不能静默择优。
- 最新回执仍为暂定或失败：保留旧 accepted 结果，同时清楚标记新结果的状态。
- 找不到权威字段：将声明标为 `unresolved`，不靠措辞弱化来掩盖缺证据。

## 输出合同

输出声明账本、冲突清单、修订后的读者成品和最终核对结果。通过只表示跨成品忠实于当前工件，不表示科学假设因此得到更强支持。
