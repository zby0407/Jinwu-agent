# Data Agent 权威数据自主获取与来源登记说明

## 适用范围

本次调整面向两类已有明确数据定义的太阳活动研究任务：SILSO 活动周极值复现，以及极小期极区场与下一活动周振幅的前兆关系分析。目标是在用户只提出自然语言科学问题、没有上传数据文件时，由系统取得并登记所需的公开观测数据，再进入 Data、Evidence 和后续实验阶段。

这项能力不适用于任意太阳物理数据检索。只有研究问题被识别为上述两种协议，且当前项目确实缺少协议要求的数据时，系统才会启动固定来源的数据获取。

## 原有问题

全新代码目录不包含项目运行数据。主问题 r40 从全新的 headed production WebUI 会话启动，用户只提交原始科学问题；Planning 完成审查后，Data 上下文发现任务清单中没有 SILSO 与 MWO/WSO 输入，因此以 `input_missing` 在 Data 阶段终止。该终态如实反映了当时的输入状态，但也说明系统不能在初次部署时自行补齐已经定义好的公开观测数据。

仓库原先已有权威数据获取、格式检查和项目登记函数，但需要操作者单独执行脚本。它没有接入自然语言科研闭环的 Data 入口。

## 新行为

Data 预处理现在执行以下步骤：

1. 根据任务原文和已接受的研究计划确定分析协议与必需数据集；
2. 刷新当前项目已经登记的数据，在写入 Data 上下文前核对仍缺少的必需数据；
3. 若支持的协议仍缺少必需数据，只获取缺失的数据集，不重复获取已经登记的输入；
4. 对 SILSO 月均总太阳黑子数、SILSO 官方平滑序列、SILSO 周期极值表和 MWO/WSO 极区场数据分别执行覆盖范围、字段结构、时间顺序与上游校验；
5. 将通过检查的数据登记到当前项目，刷新本任务输入清单，然后只生成一次反映最终输入状态的 Data 上下文；
6. 若官方来源不可访问、数据格式不符合预期或登记失败，运行显式报告获取失败，不把缓存样例、合成数据或未登记文件替代为观测证据。

数据来源由系统内部的固定清单决定。模型不能提供任意下载地址，也不能把其他任务、旧运行目录或仓库测试样例加入当前研究。

## 来源定位

SILSO 数据只从 WDC-SILSO 的 HTTPS 官方地址获取，并保留数据集 DOI、产品名称、许可与覆盖范围。官方地址不可用时，系统停止本次获取，不自动降级到明文镜像。

MWO/WSO 极区场数据通过 Harvard Dataverse 的持久标识解析指定公开文件，并核对 Dataverse 提供的上游校验值。来源记录保存持久 DOI、稳定的元数据接口、稳定的文件接口和 Dataverse file ID；临时下载重定向地址不进入长期来源记录。

## 输入、输出与接口

输入包括当前任务编号、项目编号、研究问题、已接受研究计划、分析协议，以及当前项目已登记数据的清单。自动获取函数只接收内部支持的数据集 ID，不接收模型给出的 URL。

输出包括：

- 项目级观测数据文件与来源说明；
- 当前任务可用的输入清单；
- Data 上下文回执，其中列出必需数据、可用数据和仍缺少的数据；
- 后续 Data 工具生成的任务级数据表、计算记录与方法限制。

项目级数据可供同一项目的新任务复用；每个科研任务仍有独立的输入清单、计算目录和审查记录，旧任务的中间结果不会自动进入新任务。

## 进入 Data 与 Evidence

极区场前兆协议在两项必需输入可用后，调用确定性数据工具构造周期边界、活动周长度、极小期极区场指标和下一活动周振幅表。SILSO 极值复现协议则使用月均、官方平滑序列和官方极值表，生成限定周期的历史复现结果。

Data 工件需要列出实际使用的数据文件、来源、单位、时间范围、样本单位、缺失项和计算产物。Evidence 随后复核数据是否与当前任务一致，时间信息集是否正确，直接观测与代理记录是否被区分，以及产物是否足以支持相应主张。数据获取成功本身不会使科学假设获得支持。

## 验证结果

来源定位测试先复现了 Dataverse 临时下载地址进入长期来源记录的问题；修正后，来源记录只保留稳定定位信息。Data 预处理测试先复现了空项目在缺少两项前兆数据时直接返回 `input_missing` 的行为；修正后，同一测试确认系统只获取缺失的数据、刷新任务输入，并在重复调用时复用已登记数据。

隔离运行 r42 进一步证明，系统能够从零输入项目自主取得两项必需数据，登记后的前兆表包含 1 行边界周期和周期 15–24 共 10 行分析周期。该轮也暴露了一个新的交接缺陷：获取前的 `input_missing` 上下文与获取后的 `inputs_available` 上下文同时留在任务目录，Data 审查误选旧记录并连续要求返修。现已把缺失检查移到上下文写入之前，并要求正式研究模式只以当前权威上下文进行专用数据审查；旧的有界测试上下文仍保持原有行为。r42 因此保留为修复前失败证据，不被改写为成功闭环。

修正后的 r44 再次从隔离空项目启动。系统自主登记两项必需数据，任务目录只形成一份 `inputs_available` 上下文，缺失列表为空；该上下文、已核验前兆表和实际 CSV 共同进入 Data 工件。独立 Data 审查在第 1 轮给出 `accept_with_limits`，没有重现旧上下文误选。审查继续保留十个相邻周期对的小样本限制、MWO 代理与 WSO 磁强计制度差异、14→15 配对的南半球窗口覆盖不足以及时间序列相关性。这一结果验证了自主获取和 Data 交接路径，不等于交互作用已经获得支持。

后续隔离运行 r52 重复验证了 Data 路径：系统在无人工附加输入时生成 11 行周期特征表与
10 行周期对表，Data 审查第 1 轮为 `accept_with_limits`。周期对范围为 14→15 至 23→24：
预测周期是 14–23，目标周期是 15–24，不包含周期 25。Data 审查仍保留混合测量制度、
样本很少、代理变量和回顾性平滑限制；该运行后来在实验设计阶段因供应商配额耗尽中断，
因而不是完整科研闭环。

最终代码状态的根测试树为 `3700 passed, 13 skipped, 8 subtests passed`，自动实验测试树为
`275 passed, 21 skipped, 18 subtests passed`，假设镜像测试树为 `79 passed, 6 skipped`。这些结果证明
实现满足已执行测试的断言，不替代 production WebUI 的真实科研运行与科学复核。

## 结论边界

本次调整证明系统具备在已定义太阳周期协议下取得、检查和登记公开观测数据的实现路径。它不证明任意太阳物理问题都能自动找到充分数据，也不证明数据的测量制度、代理变量或样本量足以识别目标机制。

对于周期 15–24 的交互问题，独立活动周对数量很少，早期极区场主要来自校准代理记录。后续实验仍需报告不确定性、留一周期影响、时间有序的样本外比较和测量制度敏感性。允许最终结果为阴性、低功效或证据受限。
