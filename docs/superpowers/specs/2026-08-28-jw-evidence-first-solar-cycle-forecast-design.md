# JW Agent 证据驱动的太阳周期假设与预测改造设计

> 日期：2026-08-28  
> 状态：对话设计已确认，书面规格待用户复核  
> 适用范围：`/home/zzz/2026tzb/8.20.4` 统一 JW/金乌 AI Scientist 运行时

## 1. 目标

本轮改造提高 **JW Agent 自身** 对太阳周期主任务的科研回答质量，重点解决：

1. 历史周期预测不稳定，却被包装成正式预测；
2. 报告提到物理前兆，但执行模型没有真实使用对应数据；
3. 假设仅因新颖或可证伪而进入“最优三项”，即使结果已不支持；
4. 不同预测时点的证据被混合，造成虚假的预测能力提升；
5. Agent 运行中断、合同拒绝和科学否定在持久化状态中难以区分。

设计采用“证据驱动的预测竞赛”：语言模型负责提出、比较和解释科研候选；宿主负责数据可用性、特征谱系、历史盲测、基线重算、合同校验和状态持久化。模型自评、文字完整度和页面成功均不能替代执行证据。

## 2. 现状与问题证据

- 现有正式 SC26 报告使用“前一周期峰值 → 下一周期峰值”作为主模型，点估计为 175.0，95% 预测区间为 `[65.8, 277.7]`。
- 该模型的历史 MAE 为 46.0，训练均值基线 MAE 为 42.4；配对改进为 -3.6，bootstrap 区间跨越零，因此没有证明预测技能。
- 报告明确记录“未使用极区磁场”。该结果不能代表新的极区物理前兆假设。
- 原负交互假设的交互项方向与预期相反，区间跨越零，且交互模型劣于加性模型。它应保留为不支持结果，不再占据现役 Top-3。
- 当前 `scientific-hypothesis-portfolio` 已区分科学支持度和研究优先级，但现有测试允许“低支持、高优先”的否定结果继续出现在组合中；本轮需要再区分“现役 Top-3”与“挑战者/被拒绝假设库”。

权威现场以实时 Git 与工件为准。`../CURRENT_STATE.md` 顶部仍包含旧分支和旧提交号，不能覆盖当前 `main@3536baf`。

## 3. 范围与非目标

### 3.1 本轮范围

- 太阳周期任务的数据与前兆特征合同；
- 假设角色、组合排名和拒绝状态；
- 严格 as-of 历史盲测与概率预测评估；
- Evidence、Integration 和 Final Release 的科学裁决；
- 运行存活状态、合同失败回执和可恢复执行；
- 新 WebUI 会话中的最终回答与可核对工件；
- 用真实新结果替换“JW Agent 三个最优假设”读者文稿。

### 3.2 本轮不做

- 不把完整表面磁通输运或太阳发电机数值同化模型作为主模型；
- 不增加开放网络 A2A 协议；
- 不通过增加大量 Agent、无限辩论轮数或更长提示词宣称能力提升；
- 不把当前 WSO 极区孔径测量重新命名为轴向偶极矩；
- 不为了得到 SC26 数字而使用尚未发生的 SC25/26 极小期数据；
- 不手工改写旧报告中的数值来模拟新实验已经完成。

完整表面磁通输运集合模型作为后续挑战者，通过本轮定义的数据和实验接口接入，不阻塞本轮交付。

## 5. 三个现役假设及预测时点

Top-3 不是三个同质的回归式，而是三个科学角色。任何比较必须先对齐预测时点。

### H1：Waldmeier 经验锚点

**陈述**：在定义固定的历史太阳周期样本中，上升时间与峰值振幅呈负相关；周期早期的上升信息可用于同周期峰值的条件预测。

**角色**：`empirical_anchor`。

**预测时点**：当前周期已经开始并积累早期上升观测后。H1 不能在前一周期极小期以前预测下一周期，也不能被描述为太阳发电机因果机制。

### H2：极区物理前兆

**陈述**：太阳活动极小期附近的极区磁场或半球极区磁通越强，下一太阳周期的峰值振幅倾向越高。

**角色**：`physical_precursor`。

**预测时点**：相邻周期极小期附近。主分析使用已登记的 MWO–WSO 校准序列与可用的 WSO 直接观测段，并分别报告测量制度敏感性。

### H3：轴向偶极矩判别假设

**陈述**：在相同周期、相同预测时点、相同训练折和相同模型复杂度下，轴向偶极矩是否比普通极区磁场或半球极区磁通更稳定地预测下一周期峰值振幅。

**角色**：`physical_discriminator`。

**预测时点**：与 H2 完全一致。H3 不预设轴向偶极矩获胜。

轴向偶极矩数据只允许来自以下两类路径：

1. 有变量定义、时间覆盖、版本和发布来源的登记数据产品；
2. 从已登记的全日面径向磁场或 synoptic map 按固定、可复算的球谐定义计算。

普通 WSO 极区孔径场、未经登记的代理量和模型生成数字不得冒充轴向偶极矩。若两条路径均不可执行，H3 终态为 `blocked_by_data`，并明确缺失数据与下一项获取动作。

## 6. 系统架构

### 6.1 总体数据流

```text
原始科研问题
  → Planning：识别预测对象、预测时点和所需证据
  → Data：登记观测量、构建 as-of 特征及谱系回执
  → Hypothesis：生成角色化候选并进入现役/挑战者/拒绝库
  → Experiment Design：冻结历史折、基线、模型和评分规则
  → Experiment Result：隔离执行并生成逐折预测回执
  → Hypothesis Update：按执行结果更新支持度和状态
  → Evidence：独立重算关键指标并审查物理含义
  → Integration：比较 H1/H2/H3，但保留预测时点差异
  → Final Release：输出读者回答、数据使用证明和限制
```

现有八阶段工作流和 `a2a-handoff-v1` 保持不变；本轮增强阶段输入合同和确定性工件，不新建第二套科研状态机。

### 6.2 前兆特征登记

Data Agent 生成 `SolarPrecursorFeatureRecordV1`。每条进入实验的特征至少包含：

- `feature_id`、`physical_quantity`、`observable_kind` 和单位；
- `source_artifact_ids`、数据产品版本及引用；
- 原始观测时间、公开可用时间和 `as_of` 截点；
- `cycle_id`、周期边界定义和目标周期；
- 数值、缺失状态和可用的不确定性；
- `measurement_regime` 与跨制度校准说明；
- 特征计算器版本和确定性参数；
- 是否满足 H1、H2 或 H3 的变量定义。

`observable_kind` 至少区分：

- `sunspot_rise_metric`；
- `polar_aperture_field`；
- `hemispheric_polar_flux`；
- `axial_dipole_moment`。

宿主根据记录生成特征使用回执。Final Release 只能声称使用回执中真实进入模型矩阵的特征。

### 6.3 假设组合与状态

太阳周期任务的组合增加 `portfolio_role` 与 `portfolio_status`：

- `portfolio_role`：`empirical_anchor`、`physical_precursor`、`physical_discriminator`、`challenger`；
- `portfolio_status`：`candidate_pending_test`、`active_top3`、`challenger_pool`、`rejected`、`blocked_by_data`。

新生成的 H2/H3 首先进入 `candidate_pending_test`。进入 `active_top3` 必须同时满足：

1. 物理量定义明确；
2. 有真实数据或明确的可获取路径；
3. 参数规模与有效周期数相称；
4. 有能改变结论的可执行检验；
5. 已形成可解释的执行结果，没有已经成立且未被解释的决定性反证。

科学支持度和研究优先级继续分开。高研究优先级只能决定“下一步是否值得研究”，不能让已经得到 `tested_no_skill` 或决定性反证的候选继续进入读者所称的“最优三项”。尚未检验的候选必须显示为待检验，不能显示为已达标。原负交互候选写入 `rejected`，保留其方向、区间、模型比较和证据引用。

### 6.4 历史盲测竞赛

每个预测实验生成 `ForecastExperimentReceiptV1`，记录：

- 假设和目标变量；
- 预测起点与数据冻结时间；
- 训练周期、测试周期和排除原因；
- 实际进入设计矩阵的特征 ID；
- 基线、候选模型和模型复杂度；
- 点预测、预测分布或区间；
- 逐折误差、汇总指标和不确定性；
- 泄漏检查、制度敏感性和执行状态。

主验证采用扩展窗口、逐周期向前预测。所有特征选择、参数选择和标准化只在当前训练窗口内完成。回顾性已知的周期边界若在预测当时尚未发布，必须记录可用性滞后，不能默认为实时已知。

固定比较对象为：

1. 当前训练窗口的历史均值基线；
2. 持续性基线；
3. 一个低维物理前兆模型；
4. 最多一个正则化加性挑战者。

H3 的两个主模型只替换前兆变量，保持训练折、目标、预处理和复杂度一致。高阶交互只有在独立实验设计中得到样本与机制支持后才能进入挑战者池，不属于本轮主模型。

主评分为逐周期 MAE 和相对训练均值基线的配对误差差。若输出概率预测，同时报告 CRPS、区间覆盖率与区间宽度。固定种子的周期级 bootstrap、留一周期分析、MWO 校准段与 WSO 直接段敏感性用于描述不确定性；不以单个相关系数或训练拟合优度宣称预测技能。

预测结果状态为：

- `skill_supported`：逐折 MAE 改进为正，其周期级配对 bootstrap 95% 区间下界大于零，且预注册的测量制度敏感性分析没有出现结论反转；
- `mixed_evidence`：点估计优于基线，但不确定性仍覆盖无优势，或制度敏感性明显；
- `tested_no_skill`：未优于基线；
- `blocked_by_data`：关键变量或对齐数据不可用；
- `execution_failed`：实验没有形成合法回执。

状态由确定性指标和预注册判定逻辑生成，语言模型只负责解释。

### 6.5 Agent 分工

- **Hypothesis 生成者**：提出机制、适用范围、预期方向和可证伪结果；
- **Solar Physics 审查者**：核对观测量、代理量、磁场矩和机制链是否混用；
- **Statistics 审查者**：核对预测时点、样本量、基线、泄漏和不确定性；
- **Experiment 执行者**：调用确定性数据与实验工具，不能自行填写结果；
- **Adversarial Evidence 审查者**：寻找反例周期、测量制度变化、替代解释和失败折；
- **Integration/Final Release**：只引用已持久化回执和 Evidence 接受的主张。

现有 Solar Agents 通过阶段 manifest 承担这些职责，不因本设计额外创建无边界的长驻 Agent。候选扩展和辩论有 Ralph Loop 预算；实验没有新增信息时停止。

### 6.6 最终回答合同

太阳周期预测回答必须先声明：

1. 目标周期和目标量；
2. 预测起点；
3. 当时真实可用的数据；
4. 是同周期早期预测、极小期前兆预测，还是条件情景分析。

随后给出：主预测及区间、相对基线技能、逐周期失败概况、H2/H3 对比、实际特征回执、测量制度敏感性、支持/否定/阻断结论和下一次可更新时点。

若 SC25/26 极小期尚未发生或相关前兆尚未登记，JW 对 SC26 的 H2/H3 回答必须是“尚未到达正式预测起点”或条件情景，不得生成已经完成的极小期预测。H1 的 SC25 同周期结果也不得改名为 SC26 下一周期前兆。

## 7. 错误处理与恢复

科学状态和执行存活状态分离：

- 科学状态继续表达 `active`、`blocked`、`release_ready`、`released`；
- 执行状态独立记录 `running`、`waiting_for_tool`、`interrupted`、`failed`、`stopped`；
- heartbeat 与最后进展时间只用于判断进程是否仍在运行，不改变科学 verdict。

以下失败必须形成持久化回执：

- provider/model 配置在写入线程前校验失败；
- 工具输出合同校验失败；
- 数据缺失或物理量定义不匹配；
- 实验进程中断；
- 排名结果被确定性一致性检查拒绝。

恢复使用同一 run 的幂等阶段标识。已有合法工件不重复执行；缺少合法结果的阶段重新运行。恢复操作不得把 `execution_failed` 自动改写成科学 `rejected`，也不得把死进程遗留的 `active` 当作仍在运行。

## 8. 测试与验收

### 8.1 自动测试

- 特征登记、as-of 可用性、周期映射和物理量类型单元测试；
- 极区孔径场不得通过轴向偶极矩合同的失败测试；
- 排名中 `tested_no_skill`、决定性反证或数据阻断候选不能占据现役 Top-3 的合同测试；
- 不同预测时点不得合并评分的测试；
- 扩展窗口、训练内预处理、基线重算和逐折回执测试；
- `skill_supported`、`mixed_evidence`、`tested_no_skill`、`blocked_by_data`、`execution_failed` 五类结果测试；
- provider 预校验、合同失败持久化、heartbeat 和幂等恢复测试；
- A2A 特征 ID、实验回执与 Final Release 引用一致性测试；
- WebUI 状态与读者回答渲染测试。

### 8.2 真实运行

使用 production build 的全新 headed WebUI 会话，只输入原始科研问题。运行必须真实经过 Data、Hypothesis、Experiment、Evidence、Integration 与 Final Release，并保存：

- 输入、模型与阶段回执；
- 数据和特征登记；
- 逐折预测与基线；
- Evidence 裁决；
- 最终回答和页面截图；
- 运行中断或阻断证据。

### 8.3 科学验收

- H2 工件能证明 MWO–WSO 极区数据实际进入模型；
- H3 使用真正的轴向偶极矩，或以 `blocked_by_data` 诚实停止；
- 所有历史预测遵守 as-of 边界；
- 预测结论以相对基线技能和不确定性为依据；
- 原负交互假设保留为不支持结果但退出现役 Top-3；
- H1、H2、H3 的预测时点在最终回答中可见；
- 设计冻结后再运行系统行为隐藏案例，避免针对答案调参；
- 外部太阳物理、统计和复现审查分别评价最终工件，不写回内部 verdict。

自动测试通过、真实模型调用、WebUI 完成和科学结论通过分别报告，互不替代。
