# 桌面后端启动与执行效率优化

日期：2026-10-29。基线为 PR #58 合入后的远端 main，桌面源码版本为 0.3.3。

## 改动与原因

主智能体构建存在重复子图编译。Deep Agents 0.6.12 先构建任务委派工具，再收集父任务私有状态字段并重建工具。两次构建使用相同的子智能体定义，却分别编译子图；当前默认配置共调用子图编译 22 次。

`jw/graph_build.py` 在一次主图构建内复用相同定义和状态类型对应的已编译子图，编译次数降至 11 次。上游任务工具仍按原规则重建，父任务私有字段过滤继续生效。复用范围随构建结束释放，各次构建和并发构建分别持有自己的上下文；请求指定的动态响应格式继续交由上游编译。桌面主图、复现主图和 CLI 主图共用这一入口。

`jw/utils.py` 的子智能体配置读取优先使用 PyYAML 的 `CSafeLoader`，减少长 YAML 提示词的解析开销。缺少 C 扩展的源码环境仍使用 `SafeLoader`，两条路径均拒绝 Python 对象标签。

这两项改动减少实际初始化工作量。子图在主智能体就绪前完成编译，没有新增首次任务触发的延后编译，也没有修改界面的就绪判定。

## 性能结果

在同一 WSL Ubuntu 环境、Python 3.12 和同一套依赖下比较基线与优化版。每次启动新进程、使用隔离目录和合成模型配置；构图基准禁止网络连接。两版按轮次交替先后顺序，计时期间没有并行运行测试或构建。以下使用全部样本的中位数，未启用性能剖析器。

| 测量项 | 每版样本数 | 基线 | 优化后 | 耗时下降 |
|---|---:|---:|---:|---:|
| Kimi 配置下主图构建 | 6 | 2.045 秒 | 1.821 秒 | 10.95% |
| Qwen 配置下主图构建 | 6 | 2.046 秒 | 1.908 秒 | 6.75% |
| 后端进程启动至主智能体可发送，Kimi 配置 | 4 | 2.521 秒 | 2.264 秒 | 10.17% |

独立的性能剖析确认子图实际编译次数由 22 次减少至 11 次。两种模型配置下，各轮基线与优化版的 134 个工具及模型可见参数定义完全一致。真实后端检查通过 `/api/runtime-status` 的 `canSend` 判定就绪，8 次退出后测试端口均关闭。

## 第二轮：减少重复模型请求与无效 SDK 初始化

同一用户问题在多轮工具执行中会重复调用工具选择模型。当前上游选择器仅将最后一条用户消息和可选工具的名称、说明作为输入，不使用中间的助手消息或工具结果。

`jw/middleware/tool_selector.py` 在同一会话与子图范围内复用成功的工具选择结果。用户消息、工具名称或说明、请求模型发生变化时重新选择。每次调用仍使用当前工具对象和服务商工具配置，主模型生成与工具执行照常进行。选择失败继续沿用原有错误处理并允许下次重试；下游调用失败直接返回错误。缓存仅存在于进程中，最多保存128项选择，不保存回答或工具执行结果。必选工具列表随当前工具集合重新解析。

`jw/mcp/client.py` 将 stdio 兼容补丁安装移到实际建立 stdio 连接之前。没有配置 MCP 服务时，读取配置不再加载 MCP SDK；配置了服务时，仍在智能体构建期间连接并取得工具。

### 执行流程验证

使用真实 LangGraph 和本地测试模型，在默认选择阈值下提供30个工具，执行5次工具调用后返回最终回答。同步与异步流程结果相同：

| 项目 | 第一轮版本 | 第二轮版本 |
|---|---:|---:|
| 工具选择模型请求 | 6次 | 1次 |
| 主模型请求 | 6次 | 6次 |
| 工具执行 | 5次 | 5次 |
| 工具结果与最终回答 | 两版一致 | 两版一致 |

该固定流程减少了5次重复选择请求。实际耗时收益取决于服务商延迟、任务轮数和工具集合变化频率；此表不代表真实服务商的响应时间或科研任务质量测试。首次工具选择仍需要请求模型。

复现入口为 `scripts/benchmark_tool_selection.py`。在同一依赖环境中，分别将 `PYTHONPATH` 指向基线源码和优化版源码，使用新进程执行：

## 边界与后续

- 以上是当前 WSL 源码环境的工程验证，不能直接作为 Windows 安装包的启动成绩，也不属于清空操作系统文件缓存后的冷启动测试。个别采样有波动，结果表示本次各组中位耗时的变化。
- 两轮均没有执行真实服务商请求或完整科研实验；模型调用行为使用本地测试模型验证。工具选择复用减少相同输入的重复采样，尚需在真实多步科研任务中评估其质量与延迟表现。
- 子图复用通过 Deep Agents 的 `create_sub_agent` 构建函数接入，适用于当前锁定的 0.6.12 版本。升级该依赖时应重跑构图、私有状态、动态响应格式和并发测试。
- Windows 打包与客户端启动实测见下节；macOS 打包、Windows 安装及升级流程尚未验证。

## 0.3.4：文件工具参数兼容与 Windows 启动优化（2026-10-30）

### 文件工具调用

实际模型曾将 `file_path` 写成 `path`，将 `old_string/new_string` 写成 `old_str/new_str`。新增 `FileToolArgumentsMiddleware`，仅对读取、写入和编辑工具转换这些已观察到的等价参数名。转换发生在代码内容检查之前，同步、异步以及主智能体和子智能体采用同一规则。标准名与别名同时出现且值不一致时明确拒绝，不猜测文件位置、不更改文本内容、不额外重试文件写入。转换字段记录在工具结果和日志中。

真实复测又发现模型混用了另一种 `edits` 数组接口。Qwen 提示补充实际的文件工具调用示例、单次精确替换和正确转义说明。编辑仍按工具原有规则检查目标文本是否存在、是否唯一；不通过模糊替换掩盖模型错误。
