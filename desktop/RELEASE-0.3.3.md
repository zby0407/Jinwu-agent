# 金乌 Windows 0.3.3 升级说明

本补丁包含桌面外壳 0.3.3、Python JW 0.2.3、WebUI 0.1.9。

## 启动与就绪

- 配置检查和旧数据迁移前先显示窗口；前端启动后直接打开主界面，桌面版自动使用本机后端地址。
- 可以在初始化期间编辑草稿、打开设置；后端 API 就绪后加载历史，主智能体预热完成后允许发送。
- 主智能体在后台预热；复现、写作、分析、记忆等智能体按需创建并缓存。未配置 DashScope 不阻止 Kimi 主服务启动。
- 安装包预编译 Python 字节码。日志记录首窗、配置、前端、后端 API、主智能体阶段；不显示推测的百分比。
- 不增加开机自启或后台常驻，正常退出仍清理前后端进程树。

## API 与连接设置

通过「文件 → API 与连接设置」打开；启动失败页也有入口。密钥框始终为空，已有密钥时留空保存即可保留。

DashScope 新增 `config.yaml` 的 `dashscope_proxy_mode`：`env`（默认，跟随环境/系统代理）或 `direct`（直连）。使用 HTTPX 既有代理解析，环境变量优先；Windows 在没有代理环境变量时可读取系统静态代理设置，不执行 PAC 脚本。

工作区 `.env` 中的 `JW_DASHSCOPE_PROXY_MODE` 与进程环境覆盖继续兼容，窗口显示生效方式及来源。原来 `.env` 中的 `direct` 会继续有效；仅保存 YAML 不会删除环境覆盖。需要完全改由界面控制时，应由使用者移除对应覆盖后重启应用。

保存时如果存在运行、后端排队或当前界面待发送队列，设置会暂存，空闲后应用。应用设置只重启后端，保留界面草稿。暂存设置也会在下次启动时应用。

「测试连接」仅支持 DashScope，由使用者主动点击，每次最多一次最小模型请求，总上限 30 秒，可取消；不发送研究内容，不保存表单，不在启动时自动运行。测试可能产生服务商费用。本次开发验收未调用真实模型。

错误统一显示稳定代码：`PROXY_CONNECT`、`TLS_HANDSHAKE`、`TIMEOUT`、`AUTH`、`QUOTA`、`MODEL_UNAVAILABLE`、`CONNECTION`、`UNKNOWN`。TLS 错误不会直接宣称代理有问题，单次测试也不会宣称另一条网络路径可达。

## 任务恢复

Qwen 临时网络错误由后端最多重试两次，间隔 2、5 秒；鉴权、权限、额度错误直接报告。前端不再叠加自动创建恢复运行。

失败状态和详情持续显示。修正连接或凭据后，可手动点击「从失败检查点继续」。恢复前重新核对对话、原运行和检查点，只恢复可确认的失败模型步骤；不重跑已经完成的工具步骤。重复点击被阻止。若请求已经提交但返回结果丢失，保留提交记录并等待原运行确认，避免重复运行。

## 安装与数据

安装包由本次源码重新构建，未自动发布、安装或替换当前版本。已有密钥、会话、工作区不会由构建或测试修改。更新时应先关闭正在运行的金乌，并由使用者自行运行安装包；不要删除现有用户数据目录。

测试使用仓库 `.cache/release-0.3.3/` 下的独立用户目录与合成凭据。性能数据、测试范围和未完成的验收项目见 [验证报告](VERIFICATION-0.3.3.md)。安装包未配置代码签名。
