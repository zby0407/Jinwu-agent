# 自动实验 Agent 1.0 技术说明

## 设计目标

自动实验 Agent 1.0 面向可在本地 Python 沙箱中完成的计算实验。系统负责把研究问题收敛为可执行设计、真实运行代码、核验结果与产物，并形成可追溯报告。Pi 是唯一运行宿主，负责模型、Skills、Tools、会话和用户交互；确定性 Python 核心负责合同、状态、路径、预算、执行、核验和持久化。

系统不把任何固定实验编号、模型路线或题型分类写进运行时。统计、模拟、优化、数值求解、格式转换或预测任务使用各自所需的方法；只有问题本身需要时，才出现模型、数据切分、基线、消融或稳健性分析。

当前执行边界是 WSL2/Ubuntu-E、bubblewrap、Python 3.12、无网络、锁定依赖和 `gpu_count=0`。不控制物理设备，不调用 MATLAB、R、云任务或联网安装。

## Pi 编排

Pi 扩展注册七个工具：

1. `automatic_experiment_bind_request`：绑定自然语言或高级请求并建立运行目录。
2. `automatic_experiment_inspect_inputs`：检查输入并创建不可变快照。
3. `automatic_experiment_validate_design`：一次返回合同、方法和阶段图问题。
4. `automatic_experiment_prepare_attempt`：检查当前阶段代码并建立不可变尝试。
5. `automatic_experiment_execute_attempt`：在隔离环境中真实执行。
6. `automatic_experiment_verify_result`：核验机器结果、Artifact、科学解释和阶段去向。
7. `automatic_experiment_finalize`：生成用户报告和完整审计记录。

七个 Skills 分别负责总编排、任务边界、输入兼容、最小充分设计、安全代码、故障归因以及复现与报告。Skills 提供可组合判断原则，不是题型模板。扩展只向模型开放当前阶段需要的工具，复杂参数直接使用嵌套对象，不要求生成字符串化的二次 JSON。

模型凭据从 `DASHSCOPE_API_KEY` 读取；业务空间的 OpenAI 兼容端点在 provider 配置中固定，不接受运行时环境变量覆盖。Pi 全局凭据项必须引用环境变量，不能保留会覆盖当前环境的旧密钥明文。地址只接受阿里云官方 HTTPS 兼容端点。

执行、核验和报告期间每 30 秒发送一次中文进度。模型响应临时中断时先由 Pi 完成自动重试，不会把可恢复中断提前写成实验终态；只有重试耗尽、用户停止或预算到限时，扩展才调用确定性收尾路径，保证已有证据进入正式报告。

## 合同

七个合同均沿用 `automatic-experiment-*-v1`：请求、响应、设计、worker 结果、记录、会话和入口结果。此次为 1.0 原位合同，不接受旧式单脚本设计作为新任务、继续或重放输入。

### 请求

请求记录研究问题、输入、成功要求、方法约束、种子和预算。运行级默认预算为 30 分钟、最多 5 个阶段和 6 次沙箱尝试；硬上限为 90 分钟、5 个阶段和 10 次尝试。每阶段还有独立墙钟、CPU、内存、磁盘、日志和进程预算，但不能超过运行剩余预算。

### 响应与设计

响应互斥地表示实验可设计、需要澄清或执行阻断。实验设计由研究范围、输入角色、开放式方法决策、测量与有类型结果、Artifact 计划、评价判据和 `experiment_stages` 组成。

`method_decisions` 使用开放的 `decision_key`，只记录真正影响当前实验有效性的选择。每个判断说明依据、替代方案和对结论的限制；没有科学依据时不得编造数值门槛。

一次设计包含 1–5 个阶段。每阶段声明目标、输入、前置阶段、消费和产生的 Artifact、方法、结果判定、七类阶段结果及其下一目标。检查器要求：

- 阶段依赖无环，所有引用和条件目标存在；
- 每个中间 Artifact 有且只有一个生产者；
- 前序 Artifact 只读传给后续阶段；
- 声明消费前序 Artifact 的代码必须实际读取它，绕过传递并从原始输入重算会在执行前被拒绝；
- 条件不满足的阶段安全跳过；
- 所有可达路线在运行预算内进入正式终态；
- 简单任务不得因为合同而被迫加入无关阶段。

成对比较是可选核验能力。设计明确声明差值方向后，核验器按 `baseline_minus_candidate` 或 `candidate_minus_baseline` 复算，不根据字段名称猜测公式。比较或敏感性分析必须同时计划两个条件各自的估计量和差值；同一批逐行观测上的原始值—校准值比较需要逐行成对复算。

当多个比较共用同一份证据表、但各自只覆盖其中的行子集时（例如按 `cycle_phase` 划分分周期回测、按 `quality_flag` 划分敏感性分析），设计可在该审计上声明可选的 `row_filter`（`{column, in[]}`），核验器先把证据行过滤到取值为所列值的子集，再独立复算指标；缺省或为空时使用全部行。过滤列必须存在于证据产物中，否则该审计会被报告为无法评估。

### Worker 结果与记录

Worker 结果支持数值、计数、布尔、类别和简短文本。大型数组、表格和图形必须写为声明过的 Artifact；系统记录大小、哈希和来源阶段。实验记录汇总阶段历史、条件转移、Artifact 来源关系、运行预算、尝试、环境和科学终态。

## 状态与失败分类

`state.json` 是运行权威。Pi 会话只保存当前运行引用；重新进入会话或执行“继续”时重新读取文件状态，不依赖聊天内容猜测进度。

系统区分四类问题：

- 进程或代码错误：只有能够通过改代码修复时才进入下一次技术尝试。
- Artifact 或结果合同错误：指出具体不一致；相同代码和相同错误不得无变化重跑。
- 科研结果不理想：空结果、高不确定性或部分结果是可报告结果，不消耗技术重试。
- 设计与核验定义冲突：在执行前或第一次核验时返回设计修正，不伪装成程序崩溃。

每次尝试按阶段编号持久化。已结束的历史运行不修改；`继续 <run_id>` 对未结束运行恢复完整检查点，对已结束但可补充的运行建立带来源关系的新运行。

## 输入与科学数据格式

普通输入只能来自 `inputs/` 或已完成运行的 `public/`。检查器拒绝绝对路径、路径穿越、链接、隐藏文件、秘密样式文件和内部评测目录，并在执行前创建不可变快照。

文本、Markdown、JSON、CSV 和 TSV 使用受限预览。FITS 检查 HDU、维度、类型、单位、时间与关键头信息；NetCDF 检查维度、坐标、变量、单位、日历和属性；HDF5 检查组、数据集、形状、类型、属性与外部链接；Parquet 检查 Schema、行数及 Row Group 信息。元数据检查限制读取量和声明尺寸，拒绝损坏文件、危险外部引用、压缩包装和异常大数组。

执行环境固定包含兼容 Python 3.12 的 `astropy`、`xarray`、`h5py`、`h5netcdf` 和 `pyarrow`，版本由 `requirements.lock` 锁定。

##  沙箱与不可变性

模型提交的代码经过静态策略检查，只能暴露同步 `run_experiment(context)` 入口。禁止 shell、子进程、网络、动态加载、pickle、权限修改和运行时安装。bubblewrap 不挂载项目根或用户目录；输入、代码和前序阶段 Artifact 只读，当前阶段输出目录是唯一可写位置。

每次执行记录固定命令、开始和结束时间、Windows 与沙箱退出码、资源、日志哈希、代码哈希、输入哈希、worker 结果及产物哈希。只有这些事实齐备时，报告才使用“已经执行”的表述。

##  核验、继续与复现

核验先读取真实退出状态和 worker 结果，再检查结果类型、有限数值、测量覆盖、端点、Artifact 和方法定义。对于成对比较，确定性核心从不可变输入与逐行结果独立复算目标、预测、指标和差值方向。描述性任务未请求推断检验时，核验还会检查有界 JSON 产物，拒绝把 p 值等未声明推断量藏在 Artifact 中。模型提交的摘要、判据说明和结论中的每个数值还要与已核验结果或设计前已声明依据匹配；硬阈值必须来自用户要求、已提供资料或可复算的数据推导，不能仅称作“方法标准”或“合理容忍值”。无法追溯的数字会被拒绝，不能进入用户报告。

普通任务始终建立新的独立运行，由当前模型根据本次问题和输入重新设计。系统不会因任务与历史记录相同而中断当前流程，也不会自动比较历史结果。“继续”用于未完成工作；被中断的进程不会原地续跑，只从最近完整检查点建立新尝试。只有用户明确输入 `/automatic-experiment 重放 <run_id>` 时，系统才核对指定运行的状态、设计、每个已执行阶段代码、输入、环境、记录和报告哈希，再创建新运行并逐阶段重新执行；这一复现过程不重新设计，也不复用旧输出。

##  报告

`report.md` 使用用户语言并按任务复杂度自适应。正常完成的报告采用科研汇报结构：摘要先陈述发现且不重复，数据与方法说明实际口径，结果表使用“指标—估计值—指标定义”，讨论区分解释和局限。比较条件使用其自然语言含义，不用条件 A/B 代替。代码成功、阶段完成、内部状态、字段名、文件名、分类代码、文件核验、重放命令和保存机制不进入正文；未经核对的代码变量方程也不会直接复写到报告。简单任务保持短而完整，不生成用户未请求的扩展分析建议。

`audit.md` 保存完整机器事实；`record.json` 保存结构化记录；`entry_result.json` 绑定 Pi 展示文本和文件哈希。Pi 最终展示与 `report.md` 字节一致。没有推断依据不得写“显著”，没有外部验证不得写“可泛化”，没有因果设计不得写因果结论。

任何终止点都生成报告：尚未执行时明确写明没有启动；已有有效结果时保留部分结果并说明不确定性；不能继续时说明缺少条件或安全边界。正式报告生成失败本身属于发布阻断，不得把仅有内部状态的目录算作完成运行。

## 测试与发布

确定性测试覆盖合同、两种差值方向、阶段图、只读 Artifact、预算、继续与重放、四类科学数据格式、各阶段中断报告、科研语言、结论数值追溯、安全沙箱和发布清单。PR 运行全部确定性测试和 `evals/live_cases_v1.json` 中标记的 4 个真实 Pi 冒烟任务；Nightly 运行 12 个行为任务并轮换种子；Release 对 12 个任务各运行三次。

原始 Live transcript 不进入发布文件清单，只保留整理后的 `evals/results/live_status.json` 和确定性测试摘要。历史运行目录不迁移、不覆盖，也不作为当前合同通过证据。

## 技术来源

- [AI Scientist-v2](https://github.com/SakanaAI/AI-Scientist-v2) 的公开说明支持将开放探索限制在目标明确、预算受控的流程中。
- [autoresearch](https://github.com/karpathy/autoresearch) 提供了受限修改面、固定预算和基于证据保留或拒绝实验的实践参考。
- [AutoRA](https://github.com/AutoResearch/autora) 展示了实验设计、数据收集和记录阶段的模块化组织方式。
- [ScienceAgentBench](https://arxiv.org/abs/2410.05080) 强调使用真实科学任务逐项评估代码 Agent。
- [bubblewrap](https://github.com/containers/bubblewrap) 和 Linux 资源限制提供执行原语；具体安全边界由本项目的路径策略、锁定依赖和攻击测试共同实现。
