# 自动实验 Agent 1.0 测试与使用手册

## 启动

在 PowerShell 中进入本目录并启动 Pi：

```powershell
Set-Location "E:\2026tzb\dist\自动实验agent"
pi
```

不需要附加其他启动参数。Pi 项目配置会使用千问 3.7 Max 和 `high` 推理等级。首次使用或环境变更后运行：

```text
/automatic-experiment-doctor
```

只有检查结果说明模型、凭据、锁定依赖、bubblewrap、主机隔离和网络隔离均可用时，才开始真实实验。

## 提交实验任务

### 自然语言是默认入口

输入 `/au`，用上下键选中 `/automatic-experiment` 并回车。如果命令后没有问题，Pi 会弹出输入框；用户在输入框中描述任务后才会启动 Agent，按 Esc 会取消且不调用模型。

例如：

```text
/automatic-experiment 读取 inputs/example_mean.csv，真实计算全部有限数值的均值、样本数、最小值和最大值。
```

这是一项最小链路测试，只用于确认“读入—执行—核对—报告”能够完整走通。它应直接返回四个统计量，不代表复杂科研能力演示；需要观察材料理解、方法选择和科学边界时，使用下一节的上游 Agent 接力示例。

用户不需要准备 JSON，也不需要了解阶段、合同或内部字段。问题描述最好包含：要回答什么、数据在哪里、哪些约束必须遵守、希望保存什么结果。没有说明的方法由 Agent 根据问题和数据选择。

###  上游 Agent 接力示例

常见交接可以是一份规划反馈、一份数据/特征反馈和一张处理后表格，也可以是其他零到多份材料。项目中的合成示例可直接测试：

```text
/automatic-experiment 这是一次上游 Agent 接力测试。请结合 inputs/upstream_handoff_demo/research_plan_feedback.md 与 inputs/upstream_handoff_demo/data_feature_feedback.json，使用 inputs/upstream_handoff_demo/polar_overlap_features.csv，自主设计并真实执行当前数据能够支持的有界实验。比较未校准与校准后的跨仪器一致性，并针对质量标记进行敏感性分析；同时报告包含与排除标记观测时各自的估计量及二者差值。把当前不能回答的前兆外推问题明确保留为限制，不得把合成演示数据写成真实太阳观测或第 26 太阳活动周预测。
```

这项测试应表现为：逐份理解材料作用；只执行当前数据支持的工作；明确不能回答的外推问题；所有数值来自真实执行；不把合成演示数据描述成真实科研结论。示例中的比较和敏感性检查是该任务要求，不是系统默认路线。

### 高级 JSON 是可选方式

只有需要精确声明输入、种子、单阶段资源或运行级预算时，才把高级请求放在 `inputs/` 后引用：

```text
/automatic-experiment @inputs/my_request.json
```

高级请求的默认运行时限为 30 分钟、最多 5 个阶段和 6 次沙箱尝试；允许调整，但不得超过 90 分钟、5 个阶段和 10 次尝试。普通自然语言任务会自动应用默认值。

## 观察进度与控制运行

查看状态：

```text
/automatic-experiment-status
```

状态窗口用中文显示当前阶段、已完成阶段、已使用与剩余尝试、累计执行时间、报告是否生成以及最近需要处理的问题。执行、核验或报告超过 30 秒时，Pi 会持续显示进度。

停止当前运行：

```text
/automatic-experiment-stop
```

停止会终止当前沙箱进程组，保留停止前已核验的证据并立即生成正式报告；不会关闭整个 WSL，也不会删除历史记录。

继续指定运行：

```text
/automatic-experiment 继续 <run_id>
```

这条命令可在新的 Pi 会话中使用。未完成运行从最近完整检查点继续；已经结束但需要补充工作的运行会创建一个有来源关系的新运行，旧目录保持不变。被中断的进程不会伪装成从指令中间恢复，而是从安全检查点建立新尝试。

普通任务每次都会建立新的独立运行，由千问根据本次问题和输入重新设计。重复提交相同任务时，Pi 会直接开始本次实验，不查询历史任务、不要求用户在历史方案之间选择，也不覆盖原有运行目录。

需要专门核查可重复性时，可主动复现指定运行：

```text
/automatic-experiment 重放 <run_id>
```

重放核对源运行的输入、设计、每个已执行阶段代码、参数、种子、环境和文件哈希，在新运行中重新执行，不复用旧输出，也不重新要求模型设计。
这是一项由研究者明确发起的复现检查，不会在普通任务中自动弹出。

## 理解实验行为

Agent 会根据任务选择 1–5 个阶段。简单均值、格式转换或单次模拟通常只需要一个阶段；只有后一步确实依赖已核验中间结果时，才建立条件后续阶段。

每阶段可以产生数值、计数、布尔、类别和简短文本。表格、数组、图形和科学数据文件作为带哈希 Artifact 保存，后续阶段只能只读使用。FITS、NetCDF、HDF5 和 Parquet 输入会先做有界元数据检查，异常大小、损坏文件或危险外部引用会在执行前被拒绝。

系统不会把以下情况混成“实验失败”：

- 科学空结果：实验有效，但没有观察到任务所定义的有意义效应。
- 高不确定性：结果可计算，但数据量、覆盖或误差不足以支持强结论。
- 部分结果：部分端点已核验，其他端点因明确条件未完成。
- 输入缺失或方法不匹配：不启动不可能成立的实验。
- 技术错误：代码、进程或产物可以通过修改当前阶段代码修复。
- 安全阻断：请求越过路径、网络、依赖或 GPU 边界。

只有技术错误才允许消耗修复尝试。相同代码和相同错误不能无变化地连续重跑。差值核验严格采用设计中声明的方向，负值或正值的科学含义由当前任务定义。

## 输出结果

运行目录位于 `runs/<run_id>/`。用户首先阅读：

- `report.md`：Pi 展示的正式报告。
- `public/`：可供后续任务安全引用的已核验产物。

需要审计时再查看：

- `audit.md`：输入、方法、阶段、尝试、预算、机器结果、哈希和核验细节。
- `record.json`：结构化完整记录。
- `entry_result.json`：Pi 展示文本和报告文件哈希。

正常结果以摘要、数据与方法、结果、讨论和局限性为基本结构；简单任务仍保持约 300–800 字，标准任务约 800–2200 字，多步骤任务约 1500–3500 字，失败或阻断约 300–900 字。结果表使用“指标—估计值—指标定义”，比较条件使用其自然语言含义。正文不应出现文件名、原始字段名、分类代码、条件 A/B 占位名或未经核对的代码方程；无来源的硬数值阈值应被设计检查拒绝。

无论运行在输入检查、设计、执行、核验还是保存阶段停止，都必须出现 `report.md`。如果尚未启动沙箱，报告应明确写“没有执行实验”；如果已有有效端点，报告应保留这些结果并说明未完成部分。发现只有内部状态而没有报告的运行，属于缺陷，不属于正常终态。

模型服务出现可恢复的临时中断时，Pi 会先自动重试，当前实验不会因此提前结束。只有自动重试全部失败后，系统才根据实际进度生成中断报告；这类报告会明确说明没有得到哪些实验结果，不会冒充科学空结果或证据不足。

## 维护者确定性测试

在项目目录运行：

```powershell
$env:PYTHONUTF8 = "1"
$env:PYTHONDONTWRITEBYTECODE = "1"
$env:PYTHONPATH = "src"
python -B -m unittest discover -s tests -v
```

测试覆盖：

- 七份合同与旧设计拒绝；
- 两种差值方向及已知误判回归；
- 阶段图引用、环、死分支、预算和 Artifact 来源；
- 条件跳过、只读阶段传递、多阶段真实执行；
- 精确重放、跨会话继续、用户停止和各阶段中断报告；
- 数值与有类型结果追溯；
- 描述性任务中未请求的 p 值既不能进入设计，也不能隐藏在 JSON 产物中；
- 摘要、判据说明和结论中的数字与已核验结果一致；
- FITS、NetCDF、HDF5、Parquet 的正常、损坏、超限和危险引用；
- 路径、秘密、网络、依赖、资源与沙箱边界；
- 用户报告不泄漏内部语言；
- 科研正文结构、表头和措辞符合研究汇报习惯，比较结果同时给出两侧估计值与差值；
- 设计摘要阶段数与实际阶段图一致，后续阶段不得绕过声明消费的前序结果；
- 发布清单、来源审计和三份 Markdown 文稿一致性。

运行环境检查：

```powershell
$env:PYTHONPATH = "src"
python -B -c "from automatic_experiment.service import doctor; print(doctor())"
```

发布结果写入 `evals/results/deterministic_tests.json`。若因当前 Windows 账户没有符号链接创建权限而跳过单项符号链接用例，仍必须通过硬链接、junction 和路径逃逸测试，并在摘要中如实记录跳过原因。

## 真实 Pi 行为验收

`evals/live_cases_v1.json` 定义 12 个具体任务，覆盖：上游材料接力、简单统计、关联分析、模拟、优化、FITS/NetCDF/HDF5/Parquet 往返、多阶段条件执行、科学空结果、高不确定性、部分结果、输入缺失、方法不匹配和安全阻断。

- PR：全部确定性测试，加 4 个标记为 `pr_smoke` 的真实 Pi 任务。
- Nightly：12 个任务各运行一次并轮换种子。
- Release：12 个任务各运行三次。

每次 Live 验收必须保存真实 provider、模型、`high` 推理等级、工具调用、最终文本、总耗时和各阶段耗时，并核对：

- Pi 最终文本与 `report.md` 一致；
- 正式报告确实存在；
- 所有数值能追溯到核验结果或 Artifact；
- 未执行阶段没有被写成已经执行；
- 非机器学习任务没有模型、切分、基线、消融或稳健性路线泄漏；
- 技术失败、科研空结果、证据不足和安全阻断没有混写；
- 原始 Live transcript 只作审计，不进入发布文件清单。

Live 凭据不可用时只能记录“未执行”，不能用模拟模型结果冒充通过。整理后的当前状态保存在 `evals/results/live_status.json`。

## 常见问题

### 选中命令后直接回车，为什么没有任务？

Pi 会继续弹出输入框。请在输入框中填写自然语言问题；不需要把问题先写成 JSON。

### 为什么有时只有一个阶段？

阶段数量由问题决定。能在一个阶段可靠完成的任务不应为了显得复杂而增加基线、消融或稳健性分析。

### 为什么结果不理想却没有自动重试？

科研空结果或高不确定性不是代码错误。Agent 会报告真实结果；只有明确可修复的技术问题才使用下一次尝试。

### 为什么已经停止仍然有报告？

报告是每次运行的必要终点。停止报告用于说明实际执行到哪里、保留了哪些证据，以及怎样继续，不代表所有计划阶段已经完成。

### 为什么直接调用模型成功，Pi 却提示密钥无效？

本项目使用用户级 `DASHSCOPE_API_KEY`，业务空间端点已在 provider 配置中固定。常见原因是 Pi 进程仍持有更新前的旧凭据：更新密钥后完全关闭并重新打开 Pi 所在终端即可，不需要把密钥写入项目文件，也不要再设置 `AUTOMATIC_EXPERIMENT_BASE_URL` 等会覆盖端点的环境变量。

### 如何把产物交给下一个任务？

只引用已完成运行的 `runs/<run_id>/public/...`。不要直接引用 attempt 临时目录或修改历史运行文件。
